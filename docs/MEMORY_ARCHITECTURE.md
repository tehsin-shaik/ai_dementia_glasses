# Memory Architecture: Observation → Event → Episode → Memory

MemoryCue started as "image → AI description → saved memory". To grow toward a
continuous wearable memory without breaking the existing app, saved memories now
sit on top of three lower layers. Every existing endpoint, response shape, and
Memory id is unchanged.

```text
Observation   raw evidence from one capture (image, transcript, location, detections)
    ↓ many-to-many
Event         one interpreted thing that happened, with confidence and the rule that produced it
    ↓ many-to-many
Episode       a coherent stretch of time grouping nearby events
    ↓
Memory        the user-facing saved moment (unchanged table, extra nullable columns)
```

## Tables

| Table | Purpose | Key columns |
| --- | --- | --- |
| `observations` | One capture from any device | `user_id`, `timestamp`, `source`, `image_path`, `transcript`, `latitude`/`longitude`, `location_label`, `description`, `activity`, `detected_people` (JSON), `detected_objects` (JSON), `raw_analysis` (JSON, provider output verbatim), `reviewed`, `metadata` (JSON), `embedding_ref`, `created_at` |
| `events` | Interpretation of one or more observations | `start_time`, nullable `end_time`, `event_type`, `title`, `description`, `confidence` (0–1), `inference` (`reviewed`, `legacy_migration`, or `rule:<name>`), `location`, `people`, `objects`, `embedding_ref` |
| `episodes` | Grouping of events | `start_time`, nullable `end_time`, `title`, `summary`, `inference`, `location`, `people`, `objects`, `confidence`, `created_at`, `updated_at` |
| `memories` (existing) | Saved moment | existing columns plus nullable `title`, `end_time`, `people`, `objects`, `episode_id`, `importance`, `embedding_ref`, `created_at`, `updated_at` |
| `event_observations` | Event ↔ Observation | an observation can feed several events; an event can cite several observations |
| `episode_events` | Episode ↔ Event | |
| `episode_observations` | Representative observations of an episode (images first, max 3) | |
| `memory_observations`, `memory_events` | Memory ↔ its evidence | a memory can summarize one episode or several events |

`source` is one of `browser_camera`, `iphone_camera`, `meta_glasses`,
`uploaded_image`, `other`. The backend never branches on hardware; a future
device only needs to send the same fields with its own `source`.

`embedding_ref` is a nullable placeholder. No vector store is introduced.

## Modules

| Module | Responsibility |
| --- | --- |
| `app/observation_service.py` | `create_observation()` — the single ingestion boundary. Validates user, timestamp range (2000-01-01 to now + 1 day; timezone-aware values become naive local time), source, coordinates, and text lengths; matches people to caregiver-entered `Person` rows (unknown names stay unlinked); stores the observation; optionally generates events. `analyze_image()` runs the existing vision pipeline (bundled scenes, OpenAI, or Gemini) and never raises, so a missing provider still stores the observation. `apply_analysis()` keeps the provider output in `raw_analysis` and fills only empty normalized fields. |
| `app/event_service.py` | Conservative, deterministic event rules. Reviewed observations produce `recorded_activity` and `object_seen` events at confidence 1.0. Unreviewed observations produce events only from explicit evidence: a location change from the previous observation within 30 minutes (0.6), an object detection at confidence ≥ 0.6, or a caregiver-entered person (0.7). Themed activities (`preparing_breakfast`, `preparing_food`, `leaving_home`) need at least two agreeing cue words in a 30-minute window, are capped below 1.0, and extend an existing event instead of duplicating it. An observation with no supporting evidence gets no event. `generate_events()` can re-run later over stored observations and is idempotent. |
| `app/episode_service.py` | `consolidate_episodes()` groups events that are not yet in an episode; an event joins the open episode if it starts within 20 minutes of it, otherwise a new episode starts. Titles and summaries are templated from stored fields, not generated by a model. It runs as a FastAPI background task after each capture, on demand via `POST /api/episodes/consolidate`, during seeding, and during migration — never inside the capture transaction. |
| `app/memory_service.py` | `save_reviewed_moment()` — Observation (reviewed) → Events → Memory → links → legacy `ObjectObservation`. `sync_memory_events()` carries caregiver corrections into the reviewed events and episode; observations stay as the original evidence. |
| `app/retrieval_service.py` | All reads the answer layer needs, plus timeline listings for observations, events, and episodes. |
| `app/memory_text.py` | `observation_to_text()`, `event_to_text()`, `episode_to_text()`, `memory_to_text()` — deterministic canonical text for each level. |
| `app/migrations.py` | Idempotent startup migration and backfill. |
| `app/timeline_routes.py` | New HTTP endpoints. |
| `app/retention_service.py` | `cleanup_abandoned_observations()` — deletes one user's abandoned captures; see below. |

## How a capture now flows

Reviewed save (existing UI, `POST /api/memories`):

```text
image + reviewed fields + source (default "other")
  → store image (file or MEDIA_STORAGE=database row)
  → create_observation(reviewed=True)
  → reviewed events (recorded_activity, object_seen) + any themed activity
  → Memory (same response as before) + memory_observations + memory_events
  → ObjectObservation (unchanged; drives "Where are my keys?" and cues)
  → commit
  → background: consolidate_episodes() sets memory.episode_id
```

Raw capture from any device (`POST /api/observations`):

```text
timestamp + source [+ image, transcript, coordinates, location_label, people]
  → store image → analyze_image() (optional) → create_observation(reviewed=False)
  → zero or more confidence-scored events
  → background: consolidate_episodes()
```

Browser camera (`apps/web/app/capture.ts`):

```text
CaptureSource.capture() → Capture { image, capturedAt, source, latitude?, longitude? }
  → POST /api/observations (analyze=false) → unreviewed Observation
  → optional "Analyze with AI" (POST /api/vision/analyze, stateless)
  → wearer reviews and edits
  → POST /api/memories with observation_id instead of an image
     → reviewed Observation (metadata.reviewed_from_observation_id) + Memory
     → the Memory reuses the capture's image and links to both observations
```

A capture is "the system observed something"; it becomes a Memory only when
the wearer saves it. The raw capture is never edited and stays unreviewed.
Only the owner's unreviewed captures with an image can be saved this way.
`BrowserCamera` is the first `CaptureSource`; an iPhone or glasses client
produces the same `Capture` with a different `source`, and the backend has no
per-source path. Uploaded files still save directly with `source=uploaded_image`.

## Abandoned captures

A capture nobody saves stays an unreviewed Observation with its photo. After
each new capture, a background task runs `cleanup_abandoned_observations()` for
that user only. It deletes an Observation only when all of these hold:

1. it belongs to that user and is unreviewed;
2. it was stored (`created_at`) more than `OBSERVATION_RETENTION_HOURS` ago
   (default 168, minimum 24; an invalid value stops cleanup); a missing
   `created_at` keeps it;
3. no Memory links to it (`memory_observations`);
4. no Observation names it in `metadata.reviewed_from_observation_id`;
5. every Event linked to it links only to other deletable captures, has no
   `memory_events` row, and is in no episode or only in a deletable one;
6. every Episode it or its events belong to holds only deletable events and
   representative captures, and no `Memory.episode_id` points at it.

Rules 5 and 6 repeat until nothing changes, because keeping one capture can
keep another. Anything else is kept; reviewed data never expires.

Deletion order, in one transaction under the user's consolidation advisory
lock (candidate rows are locked `FOR UPDATE SKIP LOCKED` on Postgres, and saving
a capture locks its row, so a capture being saved is skipped):
episode links and episodes → event links and events → observations → that
user's `media_blobs` no remaining Memory or Observation of any user references →
commit → the matching local files (a missing file is fine). The photo of a capture
that was saved, or shared with any kept record, is never deleted.

## Answers stay grounded

Spoken answers (`POST /api/query`) still come only from reviewed records:
saved memories, their object observations, caregiver-entered people, and the
schedule. Unreviewed observations and rule-inferred events are visible through
the timeline endpoints with their confidence, but they are never spoken as
facts. If nothing reviewed matches, the answer is the standard "I don't know"
with no sources.

Episode labels shown to the wearer (`episode_title` in `/api/memories` and
`/api/rewind`, and episode evidence in answers) are rebuilt from the episode's
reviewed and legacy events only, so an unreviewed capture or a rule-inferred
activity in the same 20-minute window never appears there. `Episode.title` on
`GET /api/episodes` still reflects every event.

Event inference runs in a savepoint: if a rule fails, the observation is kept
without events. Background consolidation runs after the capture is committed,
under a per-user advisory lock, and a failure only leaves events ungrouped.

New intent: **"What did I do today?"** (`ماذا فعلت اليوم؟`) lists today's saved
moments in order and cites the episodes they belong to. With no saved moments
it returns the unknown answer. "What am I doing today?" stays the schedule.

## Migration of existing data

`run_migrations()` runs at startup after `create_all()`, under a Postgres
advisory lock (a no-op on SQLite), and is safe to run repeatedly.

1. `ALTER TABLE memories ADD COLUMN ...` for each missing nullable column.
2. Each Memory without a `memory_observations` link gets:
   * one Observation with the memory's timestamp, location, activity,
     description, and original `image_path`; `source="other"`,
     `metadata={"migrated_from_memory_id": id, "original_source": "unknown"}`,
     `reviewed=True`; its object observations copied into `detected_objects`;
   * one Event with `inference="legacy_migration"`, confidence 1.0, and no
     `end_time`;
   * links from the Memory to both.
3. Episodes are consolidated per user.

Nothing is deleted. Memory ids, people, objects, schedules, corrections, and
image references are untouched. No end times, coordinates, people, or source
hardware are invented. Column adds use `IF NOT EXISTS` on Postgres so concurrent
cold starts cannot collide, and a consolidation failure cannot undo the backfill.

Postgres-specific behaviour (JSON round-trips, grouping queries, savepoint
rollback, advisory locks, concurrent consolidation, concurrent and repeated
migration) is covered by `apps/api/tests/test_memory_architecture_postgres.py`,
which runs when `MEMORYCUE_TEST_POSTGRES_URL` points at a disposable database
and is skipped otherwise.

## API

Unchanged: every existing route and response. Additive:

| Route | Change |
| --- | --- |
| `POST /api/memories` | optional `source` form field (default `other`); otherwise identical |
| `GET /api/memories` | items gain optional `title`, `episode_id`, `episode_title` |
| `GET /api/rewind` | moments gain optional `episode_id`, `episode_title` |
| `POST /api/query` | new `day_summary` intent |
| `POST /api/observations` | new — source-agnostic capture |
| `GET /api/observations`, `GET /api/events`, `GET /api/episodes` | new — `day`, `since`, `limit` (and `min_confidence` for events) |
| `POST /api/episodes/consolidate` | new — group pending events now |
| `GET /api/media/{filename}` | also serves images attached to the caller's observations |

No breaking API changes.
